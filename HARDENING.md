# Hardening: what the first pass leaves out on purpose

The first pass of every lesson teaches the base rule, so the reader sees the idea work
without a thicket of special cases. A real client must also survive hostile input (the
official conformance fuzzer sends plenty), so each item below comes back later, in a
hardening pass: test-first, with the vector or fuzzer case that needs it.

| Item | Where | Why it matters | What needs it |
| --- | --- | --- | --- |
| No timeout on reports | `src/obs.ts`, `report` (0.3) | A stack that accepts the connection but never answers would hang every program and test run. `AbortSignal.timeout` on each `fetch` fixes it. | Robustness, no vector |
| Why a report failed | `src/obs.ts`, `report` (0.3) | The catch says only "is the stack up?"; the real reason (refused, an HTTP error from Loki, a full disk) is thrown away. | Debugging the stack |
| A unit test for `report` without Docker | `test/` (0.3) | `report` is checked end to end (verify's `# prints: reported`), but nothing tests what it sends without a running stack. A small HTTP server inside the test can stand in. | Running the tests where Docker isn't |
| Bigints in events | `src/obs.ts`, `line` (2.7) | `JSON.stringify` throws on a `bigint`. The first event that carries a u64 (gas, a balance) needs the replacer to write it as a decimal string. | The first event with a u64 |
| Moments outside the era | `src/time.ts`, `slotAt` (0.4) | Before 12:00 UTC on 1 January 2025 `slotAt` returns a negative number, and from August 2841 on a slot no longer fits in 32 bits (timeslots are ℕ below 2^32, GP §4). Refuse both. | A clock set wrong; slots read from hostile input |
| Hex that isn't "0x" hex | `src/bytes.ts`, `fromHex` (1.1) | `fromHex` assumes the `0x` and skips two characters without looking, so `"0102"` would silently lose its first byte. Check the prefix; refuse an odd number of digits and non-hex characters with a clear error. | Hex from anywhere but the vectors |
| JSON integers above 2^53 | `test/vectors.ts`, `vectorJson` (2.6); the codecs' `fromJson` (2.4) | `JSON.parse` rounds an integer above 2^53 silently, so a u64 written as a JSON number would arrive wrong and a test could pass when it shouldn't. Today every number in the v0.8.0 vectors' JSON is below 2^53. Read big integers from their digits with a `JSON.parse` reviver (`context.source`), as a `bigint`, and accept a `bigint` in `fromJson`. | The first vector with a u64 above 2^53 in its JSON |
| Values too big for their width | `src/codec/numbers.ts`, `encodeFixed` (2.1) | ℰ_l is only defined below 2^(8l). `encodeFixed(256n, 1)` quietly writes the low byte, `0x00`, and `encodeFixed(-1n, 4)` writes `0xffffffff`. Refuse both with a `RangeError` (and test ℰ₀ = [] while you're there). | A codec bug that hands a field the wrong value |
| Naturals out of range, or cut short | `src/codec/numbers.ts`, `encodeNatural` and `decodeNatural` (2.2) | `encodeNatural` assumes x < 2^64. `decodeNatural` assumes the bytes are all there: given `0x80` (one byte announcing a second that never comes) it reads what exists and returns a wrong value instead of refusing. | Truncated blocks from the fuzzer |
| Non-canonical naturals | `decodeNatural` (2.2) | `0x8005` decodes to 5, though ℰ(5) is `0x05`. No value encodes to `0x8005`, so strictly it is not an encoding at all. lasair accepts it too; decide with the fuzzer's reference behaviour. | A fuzzer case with a padded length |
| Telling bad input from bugs | `DecodeError` (2.3 on) | A client fed a malformed block must reject the block, not crash. A distinct error type for "these bytes are not an encoding" lets the importer (and the fuzzer target) tell the two apart. | The fuzzer target (Part 20) |
| Reading past the end | `src/codec/reader.ts`, `bytes` (2.3) | `slice` past the end quietly returns fewer bytes, so a truncated block decodes into nonsense instead of being refused. Check `n` against what is left. | Truncated blocks from the fuzzer |
| Bytes left over | `decode` (2.4) | A value that decodes cleanly but leaves bytes behind is not an encoding of that value. The vector tests catch it by encoding back; hostile input needs `decode` itself to refuse it. | Blocks with trailing junk |
| Lengths larger than the input | `blob` and `seq` decoding (2.4, 2.5) | A length prefix claiming 2^60 items makes the decoder try. Every item takes at least a byte, so a length can't exceed the bytes left. | Hostile length prefixes (a denial of service) |
| Compact naturals that are too big | `natural32` (2.4) | A count above 2^32 becomes an inexact `number`. Refuse it. | Hostile counts |
| Option tags other than 0 and 1 | `option` (2.5) | Any non-zero tag is read as "present"; only 1 is an encoding. Refuse the rest. | Malformed optionals |
| A faster Writer | `src/codec/writer.ts` (2.3) | `finish` spreads every part into `concatBytes`; a structure with very many parts can hit the engine's argument limit, and copies add up. A growing buffer (start at 256 bytes, double when full) fixes both. | Large states and blocks |
| Checking the JSON | every codec's `fromJson` (2.4, 2.5) | `fromJson` trusts the vectors: `json as number`, `fromHex(json as string)`, a record reads only the fields it knows. A malformed or misnamed vector field then fails somewhere later, or not at all. Check types, ranges and byte lengths, and make records refuse missing and unknown fields. | Hand-written test data; typos in a record's field names |
| Byte strings of the wrong length | `fixedBytes` encode (2.4) | Encoding a 31-byte "hash" writes 31 bytes and shifts everything after it. Refuse anything but n bytes. | A bug that builds a short hash |
