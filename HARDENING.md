# Hardening: what the first pass leaves out on purpose

The first pass of every lesson teaches the base rule, so the reader sees the idea work
without a thicket of special cases. A real client must also survive hostile input (the
official conformance fuzzer sends plenty), so each item below comes back later, in a
hardening pass: test-first, with the vector or fuzzer case that needs it.

| Item | Where | Why it matters | What needs it |
| --- | --- | --- | --- |
| No timeout on reports | `src/obs.ts`, `report` (0.3) | A stack that accepts the connection but never answers would hang every program and test run. `AbortSignal.timeout` on each `fetch` fixes it. | Robustness, no vector |
| Why a report failed | `src/obs.ts`, `report` (0.3) | The catch says only "is the stack up?"; the real reason (refused, an HTTP error from Loki, a full disk) is thrown away. | Debugging the stack |
| A unit test for `report` without Docker | `test/` (0.3) | `report` is checked end to end (verify's `# prints: reported`), but nothing tests what it sends without a running stack. A small HTTP server inside the test can stand in. | Running the tests where Docker isn't |
| Bigints in events | `src/obs.ts`, `line` (2.7) | `JSON.stringify` throws on a `bigint`. The first event that carries a u64 (gas, a balance) needs the replacer to write it as a decimal string. | The first event with a u64 |
| Moments outside the era | `src/time.ts`, `slotAt` (0.4) | Before 12:00 UTC on 1 January 2025 `slotAt` returns a negative number, and from August 2841 on a slot no longer fits in 32 bits (timeslots are ℕ below 2^32, GP §4). Refuse both. | A clock set wrong; slots read from hostile input |
| Hex that isn't "0x" hex | `src/bytes.ts`, `fromHex` (1.1) | `fromHex` assumes the `0x` and skips two characters without looking, so `"0102"` would silently lose its first byte. Check the prefix; refuse an odd number of digits and non-hex characters with a clear error. | Hex from anywhere but the vectors |
| JSON integers above 2^53 | `test/vectors.ts`, `vectorJson` (2.6); the codecs' `fromJson` (2.4) | `JSON.parse` rounds an integer above 2^53 silently, so a u64 written as a JSON number would arrive wrong and a test could pass when it shouldn't. Today every number in the v0.8.0 vectors' JSON is below 2^53. Read big integers from their digits with a `JSON.parse` reviver (`context.source`), as a `bigint`, and accept a `bigint` in `fromJson`. | The first vector with a u64 above 2^53 in its JSON |
| Values too big for their width | `src/codec/numbers.ts`, `encodeFixed` (2.1) | ℰ_l is only defined below 2^(8l). `encodeFixed(256n, 1)` quietly writes the low byte, `0x00`, and `encodeFixed(-1n, 4)` writes `0xffffffff`. Refuse both with a `RangeError` (and test ℰ₀ = [] while you're there). | A codec bug that hands a field the wrong value |
| Naturals out of range, or cut short | `src/codec/numbers.ts`, `encodeNatural` and `decodeNatural` (2.2) | `encodeNatural` assumes x < 2^64. `decodeNatural` assumes the bytes are all there: given `0x80` (one byte announcing a second that never comes) it reads what exists and returns a wrong value instead of refusing. | Truncated blocks from the fuzzer |
| Non-canonical naturals | `decodeNatural` (2.2) | `0x8005` decodes to 5, though ℰ(5) is `0x05`. No value encodes to `0x8005`, so strictly it is not an encoding at all. lasair accepts it too; decide with the fuzzer's reference behaviour. | A fuzzer case with a padded length |
| Telling bad input from bugs | `DecodeError` (2.3 on) | A client fed a malformed block must reject the block, not crash. A distinct error type for "these bytes are not an encoding" lets the importer (and the fuzzer target) tell the two apart. | The fuzzer target (Part 20) |
| Reading past the end | `src/codec/reader.ts`, `bytes` (2.3) | `slice` past the end quietly returns fewer bytes, so a truncated block decodes into nonsense instead of being refused. Check `n` against what is left. | Truncated blocks from the fuzzer |
| Bytes left over | `decode` (2.4) | A value that decodes cleanly but leaves bytes behind is not an encoding of that value. The vector tests catch it by encoding back; hostile input needs `decode` itself to refuse it. | Blocks with trailing junk |
| Lengths larger than the input | `blob` and `seq` decoding (2.4, 2.5) | A length prefix claiming 2^60 items makes the decoder try. Every item takes at least a byte, so a length can't exceed the bytes left. | Hostile length prefixes (a denial of service) |
| Compact naturals that are too big | `natural32` (2.4) | A count above 2^32 becomes an inexact `number`. Refuse it. | Hostile counts |
| Option tags other than 0 and 1 | `option` (4.5) | Any non-zero tag is read as "present"; only 1 is an encoding. Refuse the rest. | Malformed optionals |
| A faster Writer | `src/codec/writer.ts` (2.3) | `finish` spreads every part into `concatBytes`; a structure with very many parts can hit the engine's argument limit, and copies add up. A growing buffer (start at 256 bytes, double when full) fixes both. | Large states and blocks |
| Checking the JSON | every codec's `fromJson` (2.4, 2.5) | `fromJson` trusts the vectors: `json as number`, `fromHex(json as string)`, a record reads only the fields it knows. A malformed or misnamed vector field then fails somewhere later, or not at all. Check types, ranges and byte lengths, and make records refuse missing and unknown fields. | Hand-written test data; typos in a record's field names |
| Byte strings of the wrong length | `fixedBytes` encode (2.4) | Encoding a 31-byte "hash" writes 31 bytes and shifts everything after it. Refuse anything but n bytes. | A bug that builds a short hash |
| Result tags above 6 | `src/work.ts`, `WorkResult.decode` (3.2) | Tag 7 or more indexes past the `ERRORS` list and decodes to `{ error: undefined }` instead of being refused. | Malformed work-reports |
| Dictionaries out of order | `segment_root_lookup` (3.3), and every dictionary after it | Appendix C encodes a dictionary as pairs *sorted by key*, each key once. A `seq` of pairs keeps whatever order it was given, so an unsorted or duplicated lookup encodes to bytes no other client produces. Sort on encode; refuse unsorted or repeated keys on decode. | Lookups with more than one entry; hostile reports |
| A fixed sequence of the wrong length | `seqN` encode (4.5) | `seqN(item, n)` writes whatever it is given; 599 tickets where 600 belong encode without complaint and shift everything after them. Refuse anything but n items. | A bug that builds a short list |
| Which signatures count | `src/signature.ts`, `verifyEd25519` (5.3) | The GP cites RFC 8032, which leaves room: libraries disagree about a few odd signatures (non-canonical encodings, small-order keys). noble's `verify` follows ZIP 215, as lasair's ed25519-consensus does. Pin the rule the conformance tests expect, with a test for each odd case. | The fuzzer; signatures made to probe the rules |
| A validator index past the end | `assuranceSigned` (5.3) | For an index ≥ V, `keys[assurance.validator_index]` is `undefined` and the library throws instead of answering "no". Refuse the assurance with a clear error. | `stf/assurances`: `assurances_with_bad_validator_index-1` |
| An anchor that isn't the parent | `assuranceMessage` (5.3) | The GP signs the block's parent hash; the code signs the assurance's own anchor, which the rules say must equal it. Check the anchor against the parent before trusting the signature. | `stf/assurances`: `assurance_with_bad_attestation_parent-1` |
| Keys that aren't 31 bytes | `src/trie.ts`, `leaf` (6.1) | A leaf copies the key in after the value, so a 32-byte key overwrites the value's first byte and the root comes out wrong without a word. Refuse any key but 31 bytes. | Keys built by hand; the 32-byte keys of the `trie` vectors |
| The same key twice | `src/trie.ts`, `merkle` (6.1) | Two entries with one key never split apart: `merkle` recurses past the key's last bit until the stack overflows. A state is a dictionary; refuse repeated keys. | Hostile or buggy state input |
| A trie that's rebuilt from scratch | `stateRoot` (6.1) | Every root re-hashes every entry, and every level filters every entry again. Fine for 273 entries; a real chain's state has millions. Keep the trie between blocks and re-hash only the paths that changed. | Running on a real network |
| Component numbers out of range | `src/state.ts`, `componentKey` (6.2) | A `Uint8Array` keeps only the low 8 bits of what it's given, so `componentKey(256)` quietly makes C(0)'s key. Only 1 to 16 (and 255, through `accountKey`) mean anything; refuse the rest. | A typo in a component number |
| Eight hashes where one will do | `src/shuffle.ts`, `numbersFromHash` (7.2) | Each block of eight numbers is hashed eight times, once per number. Hash each block once and read all eight numbers from it, as lasair does. | Shuffling 1,023 validators every few slots |
| Reported packages in key order | `src/history.ts`, `recordBlock` (9.2) | β's reported packages are a dictionary, encoded sorted by package hash, but `recordBlock` keeps them in the order given. Two packages reported out of order would give a different state root. Sort by hash (lasair does). | Blocks with several reports in hash-descending order |
| Rejecting bad verdicts | `src/disputes.ts`, `outcome` and the disputes step (10.1) | `outcome` calls every split wonky, but only ⌊\|K\|/3⌋ is; other splits must reject the block. Also unchecked: a verdict's vote count (exactly ⌊2\|K\|/3⌋ + 1), its age (this epoch or the last), votes sorted by index with no repeats, verdicts sorted by report with no repeats, and reports judged before. | `stf/disputes`: `progress_with_verdicts-5` (bad_vote_split), `progress_with_bad_votes_count-1`, `progress_with_verdict_signatures_from_previous_set-2` (bad_judgement_age), `progress_with_verdicts-1/2/3` (not sorted/unique), `progress_with_culprits-3` (already_judged) |
| Rejecting bad culprits and faults | `src/disputes.ts`, the disputes step (10.2) | Unchecked: a culprit's report must be in the bad set after this block; a fault's vote must contradict its report's verdict; an offender's key must be in κ ∪ λ and not already in ψ_O; culprits and faults each sorted by key with no repeats; a good verdict needs a fault. Each breach rejects the block. | `stf/disputes`: `progress_with_culprits-1/4/5`, `progress_with_faults-1/3/6/7`, `progress_with_invalid_keys-1/2` |
| Rejecting bad assurances | the assurances step (11.1, 11.2) | Unchecked: each anchor equals the parent (see 5.3's row), assurers sorted by index with no repeats, a bit set only for a core with a pending report, the validator index below \|κ\|, every signature valid. Each breach rejects the block. | `stf/assurances`: `assurance_with_bad_attestation_parent-1`, `assurers_not_sorted_or_unique-1/2`, `assurance_for_not_engaged_core-1`, `assurances_with_bad_validator_index-1`, `assurances_with_bad_signature-1` |
| Rejecting bad guarantees | the guarantees step (12.1 to 12.3) | Unchecked: guarantees sorted by core with no repeats, credentials of 2 or 3 sorted by validator, the guarantee's slot within this rotation or the last and not in the future, the core active and free, the anchor recent with the right state root, slot and belt root, the code hash and service known, enough gas, the report's size and output limits, the authorizer in the core's pool, dependencies and segment-root lookups known, no package reported twice. Each breach rejects the block. | `stf/reports`: `out_of_order_guarantees-1`, `not_sorted_guarantor-1`, `no_enough_guarantees-1`, `future_report_slot-1`, `report_before_last_rotation-1`, `bad_core_index-1`, `core_engaged-1`, `anchor_not_recent-1`, `bad_anchor_slot-1`, `bad_state_root-1`, `bad_beefy_mmr-1`, `bad_code_hash-1`, `bad_service_id-1`, `service_item_gas_too_low-1`, `too_high_work_report_gas-1`, `too_big_work_report_output-1`, `report_with_no_results-1`, `not_authorized-1/2`, `dependency_missing-1`, `too_many_dependencies-1`, `segment_root_lookup_invalid-1/2`, `duplicate_package_in_recent_history-1`, `duplicated_package_in_report-1`, `bad_validator_index-1` |
| Rejecting unwanted preimages | `src/services.ts`, `providePreimages` (14.1) | A preimage nobody is waiting for is quietly skipped, but the GP makes it invalid: every preimage in the block must be providable in the prior state, and the extrinsic must be sorted by service, then data, with no repeats. Skipping is right only for preimages that accumulation made unneeded. | `stf/preimages`: `preimage_not_needed-1/2`, `preimages_order_check-1/2/4` |
| A hostile program blob | `src/pvm/program.ts`, `unpackCode` and `deblob` (15.1) | Both trust the sizes they read: a blob shorter than its own sizes, a giant jump table or code length, a z of 0 or over 4, or a jump target off the code all slip through. deblob must also check the blob is a valid instruction sequence ending in a terminator (v_blob) and that the starting point is an instruction. A program comes from any service, so from anyone. | Hostile services; the fuzzer |
| The machine's exit details | `src/pvm/machine.ts`, `step` and `run` (15.3) | `step` moves ı on before running the instruction, so a panicking jump leaves ı at the next instruction instead of where it was, and `run` doesn't reset ı to 0 after a halt or panic as Ψ does. Neither matters until something reads ı after the machine stops (Part 16's host calls do). | Host calls; the accumulate vectors |
| A load-and-jump through its own register | `src/pvm/machine.ts`, `decisions` (15.6) | `load_imm_jump_ind` reads ω_B before it writes ω_A, as the GP says, but no test has A = B. Add one: with r0 as both, the jump must use r0's old value. | Compiled code that calls through r0 |
| Programs too big for memory | `src/pvm/standard.ts`, `standardProgram` (15.8) | Y has no answer (∅) unless 5Z_Z + Q(\|o\|) + Q(\|w\| + zZ_P) + Q(s) + Z_I ≤ 2^32, and the arguments must fit in Z_I; then Ψ_M panics without running anything. `standardProgram` lays out whatever it's given. A service's code comes from anyone. | Hostile services; the fuzzer |
| Charging from the middle of a block | `src/pvm/gas.ts`, `stepWithGas` (15.11) | The GP charges the block that ı is in, from its start (𝔏(ı)); `stepWithGas` charges from ı itself. The same whenever ı starts a block, which is always so far. A machine resumed or started mid-block (an inner machine, Part 16) needs 𝔏. | Inner machines (machine/invoke host calls); the accumulate vectors |
| grow_heap out of gas | `src/host.ts`, `growHeap` (16.3) | The GP leaves the gas as it was when growing would cost more than is left. The 0.8.0 test vectors follow a later change (GP PR 533): the gas is drained to zero, so all of it counts as used. Also unhandled: writable pages with gaps between a and b, where h = a + c undercounts. | `stf/accumulate`, traces that run a service out of gas while it grows its heap |
